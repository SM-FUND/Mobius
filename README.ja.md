# Mobius 取引所間アービトラージエンジン

Mobius は複数の取引所における同一銘柄のスプレッドを監視し、戦略とリスク条件を満たしたときに 2 つのレッグを同時に発注します。戦略、ポジション、約定、損益はコンソールで管理できます。

このリポジトリはコンパイル済みの Linux x86_64 プログラムだけを公開しており、ソースコード、ユーザー設定、データベース、取引用の認証情報は一切含みません。プログラムは自分のサーバーにインストールし、API キーはそのサーバーにだけ保存されます。

## ご利用の前に

本ツールはデジタル資産の取引を伴います。スプレッドがあっても利益が出るとは限らず、実際の結果は次の要因に左右されます。

- 取引手数料、資金調達率、その他のプラットフォーム手数料
- ネットワーク遅延、相場の変動、板の厚み
- スリッページ、部分約定、2 つのレッグの約定タイミングのずれ
- 取引所 API・WebSocket の障害やルール変更
- 証拠金、ポジション、強制清算、口座権限に関するリスク
- お住まいの国・地域の法律、規制、プラットフォームへのアクセス制限

まずは少額で試し、口座、方向、数量、リスク設定が正しいことを確認してから規模を広げてください。本ツールは投資助言ではなく、利益を約束するものでもありません。取引、口座、資金に関するリスクは利用者自身が負います。

## ワンライナーでインストール

新しい Ubuntu サーバーで実行します。

```bash
curl -fsSL https://raw.githubusercontent.com/SM-FUND/Mobius/refs/heads/production/install.sh | sudo bash
```

インストールスクリプトは次の処理を行います。

1. 最新リリースをダウンロードして SHA-256 を検証し、検証に失敗した場合はただちに終了します。
2. システムユーザー `mobius` を作成し、自動起動する systemd サービスとしてプログラムをインストールします。
3. サービスを起動し、コンソールのアドレスと**初期化コード**を表示します。

インストールに成功すると、最後に次のような出力が表示されます。

```text
[mobius] Mobius 0.3.0+62 installed.
[mobius] Console:    http://203.0.113.10:8787
[mobius] Setup code: ABCD-EFGH
```

**初期化コードは大切に保管し、スクリーンショットを他人に見せないでください。** 認証アプリを登録するまでは、「IP + 初期化コード」を知っている人なら誰でもコンソールを乗っ取れます。

> インストールと運用コマンドのターミナル出力は英語です。AWS Lightsail などクラウド事業者のブラウザターミナルには CJK フォントがないことが多く、文字化けするためです。コンソール画面は「設定」で中国語または英語に切り替えられます。

### ポート 8787 を開放する

クラウドサーバーには通常、セキュリティグループやファイアウォールがあります。TCP 8787 を開放しないと、ブラウザからコンソールを開けません。

- クラウド事業者の「セキュリティグループ / ファイアウォール」でインバウンドルール TCP 8787 を追加し、送信元はできるだけ自分の IP に限定します。
- サーバーで ufw を有効にしている場合：

```bash
sudo ufw allow 8787/tcp
```

## 初回ログイン

1. ブラウザで `http://<サーバー IP>:8787` を開きます。
2. インストール時に表示された初期化コードを入力します。
3. Google Authenticator、Microsoft Authenticator、1Password などの認証アプリで、画面の QR コードを読み取ります。
4. 認証アプリに表示された 6 桁のコードを入力すると、登録が完了してコンソールに入れます。

登録が完了すると初期化コードはすぐに無効になり、以後は 6 桁のコードだけでログインします。ログインセッションの有効期間は 12 時間です。

## 取引所 API キーの設定

コンソールの「設定 → 取引所」でアカウントを追加します。API キーを作成するときは、必ず次のようにしてください。

- **取引と読み取りの権限だけを有効にし、出金権限は無効にする**
- **IP ホワイトリストにこのサーバーのグローバル IP を設定する**
- 取引所ごとに Mobius 専用のキーを作成し、他のプログラムと共用しない

保存した API キーはサーバー上で暗号化保存され、コンソールに平文で表示されることはありません。

## セキュリティについて

- コンソールは TOTP 認証アプリを登録するまで使えません。初期化コードを持たない人が先に乗っ取ることはできません。
- 初期化コードや 6 桁のコードを続けて間違えるとロックされます。同じ IP から 5 回間違えると 1 分間ロックされ、以後は毎回 2 倍、最長 1 時間です。
- 同じ 6 桁のコードは 1 回しか使えず、傍受されても再利用できません。
- **コンソールは HTTP でアクセスするため、通信は暗号化されません。** セッションや画面に入力した API キーは平文でネットワークを通ります。そのため上記の「出金無効 + IP ホワイトリスト」は必須で、セキュリティグループで 8787 の送信元も自分の IP だけに許可することを推奨します。暗号化が必要な場合は、証明書付きのリバースプロキシを前段に置いてください。

## オンライン更新

新しいバージョンが公開されると、コンソール右上に新バージョンのボタン（`新版本 vX.X.X.X`）が表示されます。更新を実行すると：

1. 稼働中の戦略がまず自動で停止されます。
2. サーバーが新バージョンをダウンロードして検証し、データをバックアップしてからバージョンを切り替えます。サービスの再起動には約 1 分かかります。
3. 新バージョンの起動後、停止していた戦略は自動で元の状態に戻ります。
4. 新バージョンの起動に失敗した場合は、旧バージョンと更新前のデータに自動でロールバックします。

更新が終わるとページは自動で再読み込みされます。インストールコマンドを再実行する必要はありません。

すべてのバージョンと更新内容は [Releases](https://github.com/SM-FUND/Mobius/releases) で確認できます。

```bash
# サービスの状態を確認
sudo systemctl status mobius

# 認証アプリを紛失した場合：認証アプリとすべてのログインセッションを消去し、新しい初期化コードを表示

# 最新バージョンを再インストール（データと設定は保持）
curl -fsSL https://raw.githubusercontent.com/SM-FUND/Mobius/refs/heads/production/install.sh | sudo bash
```

## ファイルの場所

| パス | 内容 |
|---|---|
| `/opt/mobius/current` | 実行中のプログラム（`/opt/mobius/releases/<バージョン>` を指す） |
| `/var/lib/mobius/data` | アカウント、台帳、相場履歴などのデータ（暗号化された API キーを含む） |
| `/var/lib/mobius/backups` | 直近のオンライン更新前に取得したデータのバックアップ |
| `/etc/mobius/mobius.env` | サービス設定 |

バックアップする場合は `/var/lib/mobius/data` 全体をコピーし、暗号化して別の場所に保管してください。

## よくある質問

**ブラウザでコンソールを開けない**

まずサービスが動作しているか確認します：`sudo systemctl status mobius`。サービスが正常なら、多くの場合クラウドのセキュリティグループか ufw で TCP 8787 が開放されていません。

**初期化コードが見つからない**

`sudo mobius-update reset-auth` を実行すると、新しい初期化コードを生成して表示します。登録済みの認証アプリとすべてのログインセッションが消去される点に注意してください。

**「验证失败次数过多」（認証の失敗回数が多すぎる）と表示される**

入力ミスが多すぎたため一時的にロックされています。表示された時間が経ってから再度お試しください（最長 1 時間）。サービスを再起動（`sudo systemctl restart mobius`）してもロックは解除されます。

**更新に失敗した**

コンソールに失敗の理由が表示され、プログラムは自動で旧バージョンにロールバックし、戦略も元に戻ります。原因の確認：`sudo journalctl -u mobius-update -n 50 --no-pager`。

**アンインストール**

```bash
sudo systemctl disable --now mobius mobius-update.path
sudo rm -f /etc/systemd/system/mobius.service /etc/systemd/system/mobius-update.path /etc/systemd/system/mobius-update.service /usr/local/sbin/mobius-update
sudo systemctl daemon-reload
sudo rm -rf /opt/mobius
```

上記のコマンドはデータと設定を残します。不要になったことを確認したら、`sudo rm -rf /var/lib/mobius /etc/mobius` で全データ（API キーを含む）を削除し、`sudo userdel mobius` でシステムユーザーを削除してください。
